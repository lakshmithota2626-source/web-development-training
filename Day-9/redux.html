Start with the problem

Why state management?

As an interface grows, shared values can become difficult to pass, update, and keep consistent.

Without a shared plan

Several components may keep their own copies of the same cart or user data. Changes can become difficult to trace or keep in sync.

Example: the cart badge says 2 while the cart page shows 3.

Use case: notice when multiple distant views depend on the same changing value.

With Redux

A central store holds shared state. Components describe events with actions, and reducers define how the state changes.

Expected result: each subscribed view reads the same current store state.

Use case: shared cart, account session, or multi-step workflow state.

Vocabulary and examples

Core Redux concepts

Each snippet is an illustrative JavaScript example. For modern Redux apps, Redux Toolkit is the recommended starting point.

Redux

A state-management library that keeps shared state in a store and changes it through dispatched actions and reducers.

// A UI dispatches an action
dispatch({ type: "cart/itemAdded", payload: item });

Expected: the store calculates a new cart state.

Use: shared state across many screens.

State

State is the current data snapshot for the app or a feature.

const initialState = {
  items: [],
  status: "idle"
};

Expected: an empty cart and no active request.

Use: represent a cart, user session, or request status.

Store

The store holds the state tree and provides methods to dispatch actions and read state. Redux Toolkit creates it with configureStore.

const store = configureStore({
  reducer: { cart: cartReducer }
});

Expected: one configured store with a cart state branch.

Use: provide shared state to the application.

Actions

An action describes what happened. It is a plain object with a type and sometimes a payload.

{
  type: "cart/itemAdded",
  payload: { id: 7, name: "Notebook" }
}

Expected: a description of the item-add event.

Use: communicate user intent to the state logic.

Reducers

A reducer receives the current state and an action, then determines the next state. Plain Redux reducers should not mutate state.

function counterReducer(state = 0, action) {
  if (action.type === "counter/incremented") {
    return state + 1;
  }
  return state;
}

Expected: increment action changes 0 to 1.

Use: define predictable state transitions.

Dispatch

Dispatch sends an action to the store. The store passes it through the reducer logic.

store.dispatch({
  type: "counter/incremented"
});

Expected: subscribers are notified when the resulting state changes.

Use: respond to a button click or completed request.

Selectors

A selector is a function that reads or derives a value from the state tree.

const selectCartCount = (state) =>
  state.cart.items.length;

Expected: for three items, the selector returns 3.

Use: reuse data access for badges, summaries, and views.

Store subscriptions

Redux integrations subscribe views to store updates. In React apps, React-Redux handles this subscription for components.

const unsubscribe = store.subscribe(() => {
  console.log(store.getState());
});

Expected: the callback runs after a dispatched update.

Use: integrations that need to react to state changes.

Recommended Redux approach

Redux Toolkit

Redux Toolkit (RTK) reduces setup and provides helpers for common Redux patterns.

createSlice

Creates action creators and a reducer from a name, initial state, and reducer functions. RTK uses Immer so mutation-like syntax produces immutable updates.

const counterSlice = createSlice({
  name: "counter",
  initialState: { value: 0 },
  reducers: {
    incremented(state) {
      state.value += 1;
    }
  }
});

Expected: RTK creates counterSlice.actions.incremented and a reducer.

Use: define the state and its update logic together.

configureStore

Sets up the Redux store with useful defaults, including Redux DevTools support.

const store = configureStore({
  reducer: {
    counter: counterSlice.reducer
  }
});

Expected: state is available under state.counter.

Use: combine feature reducers in the application store.

Connect React to the store

React-Redux and Provider

React-Redux is the official React binding. It lets components access the store without passing it through every layer manually.

Provider

Wrap the React tree in a Provider and pass it the store. Descendant components can then use React-Redux hooks.

import { Provider } from "react-redux";

root.render(
  <Provider store={store}>
    <App />
  </Provider>
);

Expected: components inside App can access this store.

Use: connect the store at the application root.

useSelector and useDispatch

Read selected data with useSelector and dispatch generated actions with useDispatch.

const value = useSelector(
  (state) => state.counter.value
);
const dispatch = useDispatch();

dispatch(counterSlice.actions.incremented());

Expected: clicking an increment control updates the selected value.

Use: connect a React component to feature state.
